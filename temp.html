    What those switches register

    
  
    

  
    
    
    
      The target is visited twice. Its capture: true listeners run during the
      descent and its bubble ones during the ascent — so the capture one still goes first,
      even if you registered it second. eventPhase reports AT_TARGET for
      both, which is why rows 4 and 5 look like one step but behave like two.
    
    
    
    
      stopPropagation() cancels the rest of the walk from wherever it is called.
      During capture the rest of the walk is the whole descent, the target, and the entire ascent
      — so everything dies. During bubble it is only the ancestors still above you, and
      everything nearer the target has already run.
    
    
    
    
      Ordering is tree position first, registration order only as a tie-break. Phase and
      depth decide everything between elements; registration order settles listeners sharing one
      element and one phase. It never reorders across elements or across phases.
    
    
    
    
      Same element, same phase: siblings survive. stopPropagation() stops the
      event reaching the next element, so another listener on that node in the same phase
      still runs — stopImmediatePropagation() is what kills those. A stop from
      the target's capture listener does kill its bubble listener, though, because those
      are two separate visits.
